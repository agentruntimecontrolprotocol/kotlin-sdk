## 2. Required frontmatter

Every `.md` under `docs/` and the repo-root `README.md`/`CHANGELOG.md`/
`CONFORMANCE.md` ships YAML frontmatter consumed by the cross-SDK docs
site. Missing fields fail the site build.

Field set, in order:

```yaml
---
title: string                   # human-readable page title
sdk: "kotlin"                   # always literal "kotlin" in this repo
spec_sections: [string]         # ARCP v1.1 §s, e.g. ["6.4", "12"]; empty array for non-spec pages
order: integer                  # ordering hint within the docs section; lower = earlier
kind: enum                      # overview | install | quickstart | guide | reference | operational
status: enum                    # stable | preview | deprecated; defaults to stable
since: string                   # SDK version that introduced the page, e.g. "1.1.0"
last_reviewed: string           # ISO-8601 date, set by the doctest-and-review CI (Phase 7)
---
```

Type and value rules:

- `title` MUST NOT duplicate the H1; the site renders the title in the
  page header and the H1 in the body. Practical idiom: omit the H1, or
  keep them identical and let the site collapse duplicates (Phase 8
  picks one).
- `sdk` is always `"kotlin"` — sets the namespace under which the site
  serves the page (`/kotlin/docs/...`).
- `spec_sections` enables the cross-SDK "show all SDKs covering §6.4"
  view. Use bare section numbers as strings, no `§`.
- `order` is integer, monotonic per directory. Sparse spacing
  (10, 20, 30) so inserts don't churn the rest.
- `kind` drives sidebar grouping; the docs site refuses an unknown
  value.
- `status: preview` flags pages whose subject is behind a v1.1
  capability flag the SDK negotiates per session (see
  [`01-spec-delta.md`](./01-spec-delta.md) §C — the nine feature flags
  `heartbeat, ack, list_jobs, subscribe, lease_expires_at, cost.budget,
  progress, result_chunk, agent_versions`).
- `since` is the SDK version, not the spec version. v1.1-only pages
  carry `since: "1.1.0"`.

Site failure mode: the site generator's frontmatter validator fails
the build on a missing required field or unknown `kind`. This is the
single enforcement point — there is no in-repo schema validation step
in Phase 7. (If we want one, it's a Gradle task that runs
`snakeyaml-engine` against each page; deferred.)

Example frontmatter for `docs/guides/heartbeats.md`:

```yaml
---
title: "Heartbeats"
sdk: "kotlin"
spec_sections: ["6.4"]
order: 40
kind: "guide"
status: "stable"
since: "1.1.0"
last_reviewed: "2026-05-14"
---
```

## 3. Dokka configuration

The Dokka plugin is already declared in `:lib/build.gradle.kts:5`
(confirmed via `grep dokka`). Phase 4 will split `:lib` per
[`02-current-audit.md`](./02-current-audit.md) §H, so the Dokka
configuration moves with each new module.

Targets:

- HTML — primary output, hosted at `/kotlin/api/{module}/` on the
  cross-SDK docs site.
- Gfm (`dokka-gfm`) — Markdown output the site generator can
  optionally fold into the main navigation tree.

Per-module configuration: each of `:core`, `:client`, `:runtime`,
`:sdk`, `:ktor-server`, `:spring-webflux`, `:otel` runs `dokkaHtml` and
`dokkaGfm`. Aggregation:

- The root `build.gradle.kts` applies `org.jetbrains.dokka` and adds a
  `dokkaHtmlMultiModule` task that stitches all modules under one
  index. The site generator points at the root multi-module output;
  per-module URLs are stable at `/kotlin/api/{module}/<package>/`.
- `binary-compatibility-validator` (already declared per
  `02-current-audit.md` §F) writes `api/*.api`; Dokka picks up
  `@PublishedApi` markers but ignores internal symbols — the API dump
  is the source of truth, Dokka is the prose surface.

Cross-link from prose docs to Dokka. URL scheme: site serves Dokka at
`/kotlin/api/{module}/{package-path}/-{class-name}/`. Example:

```markdown
The client surface is [`ArcpClient`](/kotlin/api/client/dev.arcp.client/-arcp-client/).
```

Source links: Dokka source URLs point at the GitHub blob for the
current tag (Phase 9 sets `sourceLinks.remoteUrl`). Local dev builds
omit source links.

External documentation links the SDK enables in Dokka:

- `kotlinx.coroutines` — `https://kotlinlang.org/api/kotlinx.coroutines/`
- `kotlinx.serialization` — `https://kotlinlang.org/api/kotlinx.serialization/`
- `kotlinx-datetime` — `https://kotlinlang.org/api/kotlinx-datetime/`

(Set via `externalDocumentationLink { url = uri(...) }` in each
module's Dokka block.)

## 5. Voice and content rules

- No "powerful", "modern", "elegant", "robust", "leverage",
  "scalable", "performant", "enterprise-grade", "seamless". Per the
  prompt's anti-slop list and applied here too.
- No emojis.
- Cross-link spec §s and Dokka classes instead of restating either.
  Every claim that isn't pure structural prose cites a spec §, a
  TypeScript path under `typescript-sdk/`, a current-Kotlin path under
  `lib/src/main/kotlin/`, or a named Kotlin idiom from
  `02-current-audit.md` §E.
- Every fenced ` ```kotlin ` block in `docs/` and `README.md` MUST
  compile under the doctest task. Snippets that intentionally can't
  compile (e.g., a wire-format JSON shape) use ` ```json ` or ` ```text `
  instead.
- Snippets are self-contained: imports at the top, `fun main()` if the
  block is meant to run, no leaked references to outer-scope
  variables. The doctest extractor wraps each block in a synthesized
  file before compiling.
- Phase 7 cross-link: the doctest Gradle task is owned by Phase 7
  (testing). This phase only specifies the *invariant* (every kotlin
  block compiles) and the *opt-out* (a leading `// ignore` comment on
  the first line of the block).

## 6. CHANGELOG.md format

Keep-a-Changelog 1.1.0
([keepachangelog.com/en/1.1.0/](https://keepachangelog.com/en/1.1.0/));
the current `CHANGELOG.md` already follows this format and links it
explicitly. Releases adhere to Semantic Versioning.

Per-release section order: `Added`, `Changed`, `Deprecated`,
`Removed`, `Fixed`, `Security`. Omit empty sections.

`1.1.0` release notes preview (to land when Phase 4 ships):

```markdown
## [1.1.0] - 2026-XX-XX

### Added

- v1.1 capability flags: `heartbeat`, `ack`, `list_jobs`, `subscribe`,
  `lease_expires_at`, `cost.budget`, `progress`, `result_chunk`,
  `agent_versions`. Negotiated per session as the intersection of
  `session.hello.capabilities.features` and
  `session.welcome.capabilities.features` (spec §6.2).
- Three error codes: `BUDGET_EXHAUSTED`, `LEASE_EXPIRED`,
  `AGENT_VERSION_NOT_AVAILABLE`. All `retryable: false` per spec §12.
- `ArcpClient.subscribe(jobId)` returns `Flow<Event>` (spec §7.6).
- `ArcpClient.listJobs(filter, limit, cursor)` returns `JobsPage`
  (spec §6.6).
- `ArcpClient.streamResult(jobId)` returns `Flow<ByteArray>` for
  chunked results (spec §8.4).
- `arcp-otel` emits `arcp.lease.expires_at` and `arcp.budget.remaining`
  span attributes (spec §11).

### Changed

- `Welcome.capabilities.agents` accepts both `List<String>` (v1.0
  shape) and `List<AgentDescriptor>` (v1.1 shape); polymorphic
  deserializer dispatches on element type (spec §6.2).

### Removed

- All pre-v1.0 envelope types (`session.open`, `session.challenge`,
  `session.authenticate`, `stream.*`, `permission.*`, `lease.refresh`,
  `interrupt`, `checkpoint.*`) — see `planning/v1.1/02-current-audit.md`
  §G for the full list.

### Security

- Per spec §14: Host-header check on WebSocket upgrade (DNS rebinding);
  resume-window sweep on the runtime side.
```

The `1.0.0` row is absent intentionally — `02-current-audit.md` §A
establishes there is no extant v1.0 release; v1.1 is the first
conformant cut.

## 7. Anti-slop checklist

Applied to every page before merge:

- No bullet whose text is a rewording of its parent heading.
- No banned words: `leverage`, `robust`, `scalable`, `performant`,
  `powerful`, `modern`, `elegant`, `enterprise-grade`, `seamless`,
  `cutting-edge`.
- Every non-structural claim carries a citation: spec §, TS path,
  current-Kotlin path, or a named idiom (e.g.,
  "`MutableSharedFlow(replay=0, BufferOverflow.SUSPEND)`",
  "`JsonContentPolymorphicSerializer`", "`AtomicReference<BigDecimal>`
  CAS loop" — all from `02-current-audit.md` §E).
- Code blocks compile (Phase 7 enforces).
- Frontmatter present and complete (site generator enforces).
- Page reads in ≤ 8 minutes; longer pages split.
